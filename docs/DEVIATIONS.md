# Отклонения от ТЗ, дизайна и задания на разработку

Документ ведётся по ходу работы: каждое расхождение фиксируется с причиной.
Источники истины: поведение — ТЗ на продукт, внешний вид — макеты дизайна,
технические решения — задание на разработку.

## Решения пользователя (21 сентября 2026)

| Вопрос | Ответ | Что это меняет |
|---|---|---|
| Видео для подсчёта | Пока нет | Ядро подсчёта проверяется на публичном ролике `people-detection.mp4` (Intel IoT devkit sample videos). Разметка под реальное видео подбирается позже, когда файл появится |
| Площадка | Сервер Beget | Основной целевой запуск — Linux-сервер без видеокарты. Устройство по умолчанию: CPU; режим анализа `auto` на таком железе выберет предрасчёт. Docker-сборка обязательна, а не «дополнительно» |
| Проверка точности | Не проверяем | Приёмка M1 по расхождению с ручным подсчётом (задание, раздел 2) не выполняется. `docs/ACCURACY.md` заполняется цифрами системы без эталона. Целевые 5–10 % подтвердить нечем — это принятый пользователем риск |
| Первая учётная запись | Логин `admin`, пароль генерируется | При первом старте система создаёт `admin` со случайным паролем и печатает его в консоль один раз. Пароль в репозитории не хранится |

## Технические отклонения

| Что | Как в задании | Как сделано | Почему |
|---|---|---|---|
| Детектор и трекер | «Общий детектор, отдельный трекер на каждый источник» | На каждый источник свой экземпляр модели с `track(persist=True)` | Состояние трекера в Ultralytics привязано к экземпляру модели; отдельный экземпляр на источник надёжнее и не зависит от версии библиотеки. Для моделей класса «n» это единицы мегабайт на источник |
| Версия Ultralytics | `ultralytics` без указания версии, модель `yolo26n` | `ultralytics>=8.4.157` | Версии 8.3.x на macOS требуют `numpy<2`, что конфликтует с остальными зависимостями; семейство YOLO26 доступно начиная с 8.4 |
| Параллельный инференс | «один рабочий поток инференса, который обходит источники по кругу» | Общий замок вокруг вызова модели: потоки источников ждут очереди | Достигается то же самое меньшей кровью. Без замка Metal падает с `A command encoder is already encoding to this command buffer` — ускорители не переносят одновременные вызовы из нескольких потоков. Проверено: два источника по 12 кадр/с работают одновременно без сбоев |
| Выбор режима анализа | Измерение скорости при старте источника | Измерение на первых кадрах уже идущего воспроизведения | Видео начинает играть сразу, а не после замера: у пользователя не бывает «чёрного экрана без объяснений». Пока идёт подготовка анализа, кадры показываются, счётчики честно стоят, состояние — «модель прогревается» с процентом |
| Пути в `.env` | — | Относительные пути считаются от корня проекта | Иначе запуск `uvicorn` из `backend/` и `python -m app.cli` из корня складывали бы базу и видео в разные места |

## Расширения сверх ТЗ

| Что | В ТЗ | Как сделано | Почему |
|---|---|---|---|
| Прямой поток с камеры | «В MVP камер нет» (раздел 1.2): источник — файл по кругу | Второй тип подключения — ссылка на HLS, RTSP или HTTP-поток. Анализ только в реальном времени, буфер выравнивает кадры по меткам времени, переподключение при обрыве | Просьба пользователя от 25 сентября 2026: подключить живую камеру из России, где ходят люди |
| Профиль модели «Дальний план» | Три профиля | Четвёртый: yolo26n с входом 1920 | Для широкого плана: на площади при входе 960 модель находила втрое меньше людей |

## Отклонения от дизайна

| Что | Как в дизайне | Как сделано | Почему |
|---|---|---|---|
| Тёмная тема | В макетах не передана; ТЗ (раздел 8) требует обе темы | Тема одна — светлая. Переключателя нет, личной настройки темы нет | Решение пользователя от 21 сентября 2026: «убери тёмную тему, будет только светлая». Инвариант ТЗ № 10 в этой части не выполняется осознанно. Токены оформлены переменными, поэтому вторая тема при желании добавляется без правки компонентов |
| Смена пароля в интерфейсе (P2) | Есть в ТЗ | Делается командой `python -m app.cli set-password` | Управления учётными записями в интерфейсе нет по рамкам проекта; пароль в веб-форму мы не принимаем |
| Проверка разметки тестовым прогоном (P1) | Спроектирована | Не сделана | Требует отдельного прогона по черновой разметке без записи в реальные данные — работа на отдельный этап. Вместо него разметка проверяется правилами (самопересечения, порядок точек, сторона входа) и сразу видна на кадре |
| Сборка Docker | Обязательна для сервера | Написана, но не собрана | Docker на машине разработки не установлен. Файлы `Dockerfile` и `docker-compose.yml` готовы, первую сборку придётся сделать на сервере |
| Поминутная детализация демо-набора | — | Поминутные интервалы за последние трое суток, часовые — за 30 | Тридцать суток поминутно — это около 170 тысяч записей на источник: сборка занимала бы минуты, а разницы на графиках недели и месяца не видно |
| Нетипичный трафик | Тип события есть в ТЗ | Правило не включено | Ему нужен накопленный профиль «этот час этого дня недели» минимум за неделю. На реальных данных MVP он почти не сработает, на демо-данных его заменяют остальные правила |
