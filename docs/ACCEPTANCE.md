# Приёмка (этап M6)

Проход по чек-листу ТЗ (раздел 11) и по списку ошибок прежнего прототипа
(раздел 9). Каждый пункт помечен: **сделано**, **упрощено** или **не сделано** —
с причиной. Проверка выполнена на чистой установке: база создана с нуля,
источники и учётная запись появились при первом старте.

## Ошибки прежнего прототипа (ТЗ, раздел 9)

| Ошибка | Как сейчас |
|---|---|
| 1. Зоны и линии не показывались поверх изображения | Рисуются вместе с числом людей в зоне и счётчиками по линии |
| 2. Разметка делалась вне продукта | Есть экран разметки поверх кадра с опорными точками людей |
| 3. Журнал был нередактируемым | Статус меняется, автор, время и комментарий пишутся в историю; конфликт при одновременной правке виден |
| 4. Не было переходов к источнику и моменту | Из любого события — к источнику, к деталям, к динамике вокруг эпизода |
| 5. Поиск и уведомления были заглушками | Оба работают |
| 6. Индикатор состояния потока был статичным | Показывает реальное положение и список проблемных источников |
| 7. В отчётах не было периода; период не влиял на журнал | У отчёта свой период и детализация; журнал живёт по глобальному периоду |
| 8. Таблицы не сортировались и не выгружались | Сортировка по колонкам, страницы, выгрузка CSV и Excel |
| 9. Технические показатели были в одной ячейке | Частота кадров, задержка и уверенность — отдельными строками со своими единицами |
| 10. Настройки жили в браузере и подтверждались `alert` | Хранятся на сервере, влияют на анализ, есть пометка изменений и сброс; системных окон нет |
| 11. Статусы выводились на английском | Всё через словарь; неизвестное значение показывается как «Неизвестно» и пишется в консоль |
| 12. Направление изменения не отличалось от оценки | Разведены: рост очереди — ухудшение, рост пропускной способности — улучшение, рост входов — нейтрально |
| 13. Профиль пользователя ни на что не влиял | Определяет стартовый раздел и контур после входа |
| 14. Источники нельзя было добавить и проверить | Добавление, правка, включение и выключение, проверка доступности, мягкое удаление |
| 15. Контур назывался «зоной», статусы назывались по-разному | Терминология из раздела 2 ТЗ, подписи статусов одинаковы везде |

## Что осталось за рамками

| Пункт | Причина |
|---|---|
| Тёмная тема | Решение пользователя: тема только светлая |
| Проверка разметки тестовым прогоном (P1) | Требует отдельного прогона по черновой разметке без записи в реальные данные |
| Событие «Нетипичный трафик» | Нужен профиль «этот час этой недели» минимум за неделю наблюдений |
| Смена пароля в интерфейсе (P2) | Делается командой `python -m app.cli set-password`; пароли в веб-форму не принимаем |
| Сверка точности подсчёта с ручным | Решение пользователя: точность не проверяем (см. `DEVIATIONS.md`) |
| Сборка Docker-образа | На этой машине Docker не установлен, поэтому `docker compose up --build` не проверялся. Сам файл сборки написан под сервер без видеокарты: torch ставится из CPU-индекса |

## Проверка запуска

| Что проверено | Результат |
|---|---|
| `make install`, `make install-web` | Окружение бэкенда и зависимости фронтенда ставятся |
| `make dev` | Поднимает бэкенд на :8000 и фронтенд на :5173 одной командой |
| Первый старт на чистой базе | Создаются четыре источника из ТЗ и учётная запись `admin`; пароль печатается в консоль один раз; лежащее в `data/videos` видео с разметкой подхватывается, и источник сразу считает |
| `make test`, `make test-web` | 70 тестов бэкенда и 23 теста фронтенда — зелёные |
| `make build-web` | Интерфейс собирается; собранные файлы отдаёт сам бэкенд |
